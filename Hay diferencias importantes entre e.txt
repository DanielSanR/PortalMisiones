Hay diferencias importantes entre el Figma y lo que tenemos modelado. Te las detallo:
                                                                                                                                                                                  
  ---
  1. Navegacion jerarquica de 3 niveles (lo mas critico)                                                                                                                          
                                                                                                                                                                                    El Figma muestra un flujo Categoria > Sub-categoria > Tramites, no una lista plana:                                                                                             
                                                                                                                                                                                  
  Home
   └─ Categorias (cards grandes: "Automotor, transporte y transito", "Denuncias", etc.)                                                                                                  └─ Sub-categorias (cards chicas: "Licencia de conducir", "Infracciones", "Tasas", etc.)                                                                                    
           └─ Tramites individuales ("Primera licencia para clases particulares", etc.)

  Nuestro modelo actual: Etiqueta tiene un campo categoria: string plano. No hay entidad de Categoria como tal ni jerarquia padre-hijo.

  Lo que falta: Una entidad Categoria con relacion padre-hijo (o convertir Etiqueta en un arbol de 2 niveles). Las "categorias" del home son el nivel 1, las "sub-categorias" de  
  categoria.png son el nivel 2, y los tramites cuelgan del nivel 2.

  ---
  2. Destinatario / Audiencia (no existe en el modelo)

  El home tiene 3 tabs que segmentan TODO el contenido:

  - Tramites para la Ciudadania
  - Tramites para Organizaciones y empresas
  - Tramites para Organismos

  Ademas en la pagina de categoria hay un dropdown "Todos los destinatarios" como filtro.

  Nuestro modelo actual: No existe el concepto de destinatario. No hay campo ni entidad para esto.

  Lo que falta: Un campo destinatario en Tramite (enum o FK a tabla catalogo), o una entidad Destinatario con relacion N:N.

  ---
  3. Modalidades mas granulares

  El Figma muestra 4 modalidades como tabs de filtro:

  ┌──────────────────────────────────┬───────────────────────┐
  │              Figma               │ Nuestro modelo actual │
  ├──────────────────────────────────┼───────────────────────┤
  │ Digital de punta a punta         │ Digital               │
  ├──────────────────────────────────┼───────────────────────┤
  │ Digital con instancia presencial │ Mixto (?)             │
  ├──────────────────────────────────┼───────────────────────┤
  │ Presencial con apoyo digital     │ Presencial (?)        │
  ├──────────────────────────────────┼───────────────────────┤
  │ Informativo / derivacion         │ No existe             │
  └──────────────────────────────────┴───────────────────────┘

  Lo que falta: Actualizar las modalidades seed a las 4 que muestra el Figma. "Informativo / derivacion" es un tipo nuevo que indica que el portal solo informa, no hay tramite   
  real que iniciar.

  ---
  4. Ficha de tramite con campos estructurados (no un texto libre)

  tramites2.png muestra un acordeon con secciones especificas:

  - Guia de Requisitos Generales
  - Costos y modalidad de pago
  - Formularios e instructivos
  - Contacto
  - Sitio Web

  Nuestro modelo actual: Solo tiene resumen y descripcionLarga (un blob de texto). No hay campos separados para requisitos, costos, formularios ni contacto.

  Lo que falta: Agregar campos estructurados al Tramite:

  // Campos nuevos necesarios en Tramite
  requisitos: string | null;          // texto o HTML
  costos: string | null;              // texto o HTML
  formularios: string | null;         // texto o HTML (links a PDFs)
  contacto: string | null;            // texto o HTML

  O una tabla auxiliar tramite_secciones si se quiere que sea dinamico.

  ---
  5. "Temas" en la navegacion

  El nav del Figma tiene: Inicio | Tramites | Temas | Organismos | Mi Portal

  "Temas" probablemente mapea a nuestros Eventos de Vida ("Voy a tener un hijo", "Quiero emprender"), pero hay que confirmarlo con el diseñador.

  ---
  6. Badge de organismo responsable en la ficha

  tramites2.png muestra arriba de la ficha: "Informacion otorgada por Ministerio de Transporte" y tres badges:

  - Direccion de Transporte (organismo)
  - Digital con instancia presencial (modalidad)
  - Ciudadanos (destinatario)

  Esto confirma que el destinatario es un dato visible del tramite, no solo un filtro.
